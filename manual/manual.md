## 一、整体结构

| 部分 | 位置 | 作用 |
|---|---|---|
| 访客端 | `index.html` + `assets/` | 展示项目、笔记、资料 |
| 管理端主页 | `admin/index.html` | 五个气泡的入口页 |
| 内容编辑器 | `manage/` | 在网页上增删改内容，保存即发布 |
| 壁纸管理 | `theme/` | 分别设置访客端 / 管理端壁纸 |
| 内容 | `content/` 目录 | 六个 JSON 文件，与站点代码分开存放 |
| 手册 | `manual/index.html` + `manual/manual.md` | 本页，由浏览器实时渲染 markdown |

全部页面的网址，除首页外都是目录式，不带 `.html`：

| 网址 | 页面 |
|---|---|
| `/` | 访客首页 |
| `/journal/` | 日志与碎碎念 |
| `/projects`、`/notes`、`/files` | 项目、笔记、资料 |
| `/manage/` | 内容编辑器 |
| `/theme/` | 壁纸管理 |
| `/admin/` | 管理端主页，五个气泡的入口页 |
| `/manual/` | 本页操作手册 |

横栏在访客端是 首页 / 项目 / 笔记 / 资料 / 日志与碎碎念 五项，首页指访客站 `/`；管理端各页是 首页 / 站点 / 内容 / 壁纸 四项：首页指管理端主页 `/admin/`，「站点」整页跳到访客站，随时可回。当前页高亮。

内容区六个文件各管一类：

| 文件 | 装什么 |
|---|---|
| `content/meta.json` | 站点名称、状态、GitHub 主页地址 |
| `content/projects.json` | 项目列表 |
| `content/notes.json` | 笔记列表 |
| `content/files.json` | 资料列表 |
| `content/journal.json` | 日志与碎碎念，一条一个日期 |
| `content/theme.json` | 访客端 / 管理端壁纸地址 + 历史记录列表 |

**保存机制**：编辑器点保存时，用 Git 树接口把 `projects.json` / `notes.json` / `files.json` / `journal.json` 一次性写入，落在**同一个提交**里；壁纸页点保存时，把新增图片、待删图片和 `theme.json` 一起放进**同一个提交**。都不会产生零碎记录。`meta.json`（站点名称、状态、GitHub 主页地址）没有编辑器表单，不参与保存，需要改动时直接编辑该文件。其中 `status` 显示在**访客端首页主卡的状态胶囊**里（没写就显示「站点」）；顶栏右上那颗小胶囊是固定标签，访客端一直是「站点」，管理端一直是「管理端」。

**文件实物放哪**

上面六个 JSON 只装文字。图片和附件是另外落盘的：

| 上传的东西 | 落在仓库哪里 | 命名 |
|---|---|---|
| 正文插图（编辑器里「插入图片」） | `assets/uploads/images/` | `<时间戳>-<原文件名>`，自动压到长边 2400、质量 0.82 |
| 附件（「添加附件」，支持选整个文件夹） | `assets/uploads/projects/<项目 id>/` 或 `assets/uploads/notes/<笔记 id>/` | `<时间戳>-<原文件名>`，子目录结构保留 |
| 访客端壁纸 | `assets/img/wallpaper-guest-<时间戳>.<扩展名>` | 时间戳命名，不覆盖旧图 |
| 管理端壁纸 | `assets/img/wallpaper-admin-<时间戳>.<扩展名>` | 同上 |
| 手册正文 | `manual/manual.md` | 固定文件名 |
| 站点名 / 状态 / GitHub | `content/meta.json` | 手工编辑 |

三条规矩：

- 图片和附件**走管理端上传**，不要手工往 `assets/` 里塞文件。JSON 里存的是 `/assets/uploads/...` 的绝对路径，手放的文件没有任何条目引用它，站点上看不见。
- 单个文件上限 20MB，超了会提示改放网盘（`files.json` 里的条目本来就允许外链）。
- 文字在 `content/*.json`、实物在 `assets/uploads/`，两边靠条目里的路径字段（正文的 `![](路径)`、附件的 `path`）连起来。删附件时先删 JSON 里的引用，再删仓库里的文件。

**关键约束**：不要在管理端开着的时候，又去 GitHub 网页上改 `content/` 里的四个列表文件。管理端保存会整体重写它们，两边同时改会互相覆盖。

**栏目是固定的**：项目、笔记、资料三个板块始终存在。某一类没有内容时显示「暂无内容」，不会隐藏入口。

## 二、日常编辑

### 进入管理端

打开 <https://liuyun2026.github.io/admin/> 进入管理端主页（和访客端首页同款布局，标题后多「管理端」小字，气泡为访客端三个 + 内容 + 壁纸共五个），点「内容」气泡进入编辑器，或直接访问 `/manage/`。第一次需要填令牌（见第三节），之后这台设备会自动记住。

### 界面

编辑器和壁纸页的顶栏与访客端一致：品牌、首页 / 站点 / 内容 / 壁纸，右侧是连接状态、GitHub 与操作手册图标，当前页高亮。点品牌回管理端主页。连接状态为「未连接」时状态点显示红色，连接后转为绿色。

左侧四个标签切换 **项目 / 笔记 / 资料 / 日志与碎碎念**，点列表里的一条，右侧出现对应表单。

- 「+ 新建一条」：加新内容，填完记得保存
- 「删除这一条」：需要二次确认
- 底部「保存并发布」：把所有改动一次性提交
- 左侧底部「操作手册」：就是本页

### 各字段的写法

**项目**

| 字段 | 说明 |
|---|---|
| 标识 id | 英文、唯一，决定地址 `/project/<id>`，不要和已有的重复 |
| 分类 | 下拉选 硬件 / 软件 / 文档，下面的输入框可手填自定义分类，用于项目页筛选 |
| 状态 | 下拉选 进行中 / 已完成 / 计划中 / 开源 / 搁置，下面的输入框可手填；含「进行中」显示黄色，「固化/在用」显示绿色，「开源」显示蓝色 |
| 摘要 | 列表页与详情页开头那段话，控制在一到两行 |
| 参数表 | 每行一条，写成 `名称 \| 值`，会渲染成表格 |
| 标签 | 用顿号或逗号分隔 |
| 链接 | 每行一条，写成 `文字 \| 地址`，会渲染成按钮，可用于跳转到 GitHub 仓库 |
| 正文 | 长文说明，支持表格、图片、链接，语法见第六节 |
| 附件 | 上传文件或整个文件夹，显示在正文末尾供下载 |

**笔记**

| 字段 | 说明 |
|---|---|
| 标识 id | 英文、唯一，决定地址 `/note/<id>` |
| 日期 | 点开是日历，选到具体某一天；存成 `2026-11-06`，列表页直接显示。日历标题写到月（2026 年 11 月），按钮上显示「2026 年 11 月 6 日」 |
| 正文 | 每行一句，语法见第六节 |
| 附件 | 与项目相同 |

**资料**

资料只记录链接，不上传文件本身。

| 字段 | 说明 |
|---|---|
| 类型 | 下拉选 数据手册 / 手册 / 工具 / 图片 / 其他，也可手填；决定列表里的小标签 |
| 名称 | 列表与详情页显示的标题 |
| 链接 | 网盘或任何外部地址，填了以后条目可点击跳转 |
| 大小 | 可留空 |
| 说明 | 一两句话，展开后显示 |

**日志与碎碎念**

一条一天，按日期倒序排在 `/journal/`。

| 字段 | 说明 |
|---|---|
| 日期 | 日历选到某一天，存 `2026-11-07` |
| 心情 / 标记 | 下拉选 好嗨 / 普通 / 一般 / 有点累 / 很累，也可手填别的 |
| 内容 | 当天记的事，支持换行；下面有「插入图片」 |

### 正文工具栏

正文输入框上方有一排按钮，点一下就在光标处插入对应语法骨架：

| 按钮 | 插入内容 |
|---|---|
| 标题 | `## 小标题` |
| 列表 | 两条待填的列表项 |
| 引用 | `> 引用内容` |
| 代码块 | 三个反引号包好的空代码块 |
| 表格 | 两列表头加一行空表格 |
| 链接 | `[文字](https://example.com)` |
| 图片 | 打开选图，上传后自动插入图片语法 |

### 上传图片与附件

**图片**：点工具栏「图片」，选一张，它会先传到仓库，再在光标处插入 `![名称](路径)`。日志与碎碎念的「内容」框下方也有「插入图片」按钮，用法相同，图片会插在该条记录的正文里；右侧预览可直接看到效果。

**附件**：正文下方的附件区，两个按钮——

- 「添加文件」：可多选，逐个上传
- 「添加文件夹」：选择一个文件夹（Chrome 支持），保留内部相对路径，显示为 `文件夹/子文件`

存放位置：

    assets/uploads/projects/<项目id>/...
    assets/uploads/notes/<笔记id>/...
    assets/uploads/images/...        （正文插图）

**限制**：单个文件上限 20MB。更大的安装包、镜像这类，放网盘，再在「资料」栏登记一个链接。

**上传不等于发布**，每个文件上传完只是写进了仓库，附件列表要等你点「保存并发布」才会同步到内容数据里。

### 壁纸管理

`/theme/` 从上到下四块：**玻璃质感**、访客端 / 管理端两张壁纸卡、历史记录、底部「保存并发布」。

**玻璃质感**：卡片、列表、输入框这些浮在壁纸上的框，背面是模糊还是通透。分访客端和管理端两组，各点「透明」或「磨砂」：

- **磨砂**：模糊重、白膜厚，框子明显浮在壁纸上
- **透明**：几乎不糊，看得清壁纸纹理，只剩一圈边和淡淡的底

两组互不影响——访客端设成透明、管理端保持磨砂也是可以的。改完同样要点「保存并发布」，访客端下次打开才生效；当前管理端页面会立即变。


- **上传新壁纸**：选图后先在本机压缩（长边 2400px、JPEG 质量 0.82），预览立即更新，但只暂存在浏览器里，不写仓库。
- **恢复默认**：把该侧切回内置 `wallpaper.jpg`。
- **历史记录**：两列卡片，每张有缩略图、文件名、上传时间。顶部「应用到」选访客端或管理端；点蓝字「使用」把这张设为该侧壁纸；点红底「删除」会连带删掉仓库里的图片文件。
- **保存并发布**：新增图片、待删图片、`theme.json`（当前壁纸 + 历史记录）合并为一次提交。

上传、使用、删除都只在点「保存并发布」后生效，中途离开页面会丢弃未发布的改动。已连接时，仓库 `assets/img/` 里没记进 `theme.json` 的历史壁纸会自动补进列表。

## 三、令牌

管理端要改写仓库，需要 GitHub 的写入凭证。

### 首次创建

1. 打开 <https://github.com/settings/personal-access-tokens/new>
2. **Token name** 填 `liuyun-admin`
3. **Expiration** 选 1 year
4. **Repository access** 选 `Only select repositories`，只勾 `liuyun2026.github.io`
5. 点 **Add permissions**，在搜索框输入 `contents`，勾选 **Contents**，权限级别选 **Read and write**
6. 点 `Generate token`，复制 `github_pat_...` 开头的那串（只显示一次）
7. 回到管理端顶部粘贴，点「连接」

只需要 Contents 这一项权限，其他都不必开。

### 更换设备

令牌是通用字符串，不绑定设备。把生成时复制的那串存到密码管理器或备忘录，新设备粘贴即可。

生成后 GitHub 不再显示原文，丢了就去令牌页面撤销旧的、重新生成一串。

### 安全边界

- 令牌只能读写这一个仓库的文件，碰不到其他仓库
- 不能删除仓库、改可见性、加协作者
- 管理端页面本身没有密码，别人打开只看到空表单，没有令牌无法提交
- 令牌存在当前浏览器的 localStorage 里，**别人用这台电脑的浏览器就能直接保存**，公共电脑用完记得清站点数据
- 怀疑泄露时，去令牌页面点 `Revoke` 立即作废，所有设备同时失效

## 四、本地开发

站点是纯静态文件，本地起一个 HTTP 服务预览。**不要直接双击打开 `index.html`**，资源用的是绝对路径，`file://` 协议下会失效。

```bash
cd site
python -m http.server 8903
# 打开 http://127.0.0.1:8903/
```

普通的 HTTP 服务不支持深层路径（`/projects` 会 404），本地测试深层地址需要能兜底的服务器，线上由 `404.html` 处理。

### 发布

改完内容或样式后运行：

```bash
./publish.sh "本次改动说明"
```

脚本做三件事：刷新 `index.html` 里静态资源的版本号、同步 `404.html`、提交并推送。约二十秒后 GitHub Pages 完成部署。

### 目录结构

```

├── 404.html                深层路径兜底，发布时由 index.html 复制

├── theme/index.html        壁纸管理
├── manual/
│   ├── index.html          本手册的渲染页

├── admin/index.html        管理端主页
```

## 五、故障排查

**保存时提示「令牌无效或已过期」**
令牌过期或被撤销。按第三节重新生成，粘贴后重新连接。

**换壁纸不生效**
先看右上角状态点：红色是未连接，需先填令牌。上传或点「使用」之后必须点「保存并发布」。若提示错误信息，按括号里的 HTTP 状态码判断：401 是令牌过期，403 是令牌缺少 Contents 写权限，422 多为文件冲突。发布后等约二十秒再刷新访客站。

**保存成功但站点没变**
内容请求带时间戳绕开浏览器与 CDN 缓存，保存后刷新页面即是最新的。若仍为旧内容，等待约二十秒让 GitHub Pages 完成部署，或用无痕窗口确认。管理端自身的代码改动才需要等部署，可在 Actions 页面查看进度。

**页面还是旧样式**
资源版本号每次发布会变，正常会自动更新；HTML 本身有最多十分钟缓存，可用无痕窗口确认。

**发布后刷了好几次还是旧版**
两件事叠加：GitHub Pages 构建本身要几十秒；HTML 又带十分钟缓存。
页面里的版本自检会在发现构建号不一致时自动重载一次（带 `?v=` 绕开缓存）。
如果那次重载时 CDN 还没切过来，它会在 20 秒内不再重试；过一会儿再刷一次就会拿到新版。
**Ctrl+F5 强制刷新最快。**

**自动更新后片头又播了一遍**
已经处理：带 `?v=` 的那次重载不再播片头，直接出内容。

**深层地址 404**
例如 `/note/xxx` 刷新后 404。这依赖 `404.html` 兜底，该文件由 `publish.sh` 自动从 `index.html` 复制。手动改过 `index.html` 却没发布，两者会不同步。

**管理端列表空白**
`content/` 下的文件读取失败。检查 <https://liuyun2026.github.io/content/projects.json> 是否可访问。

**想恢复之前的内容**
所有历史都在 Git 里。在仓库的 Commits 页面找到目标提交，查看该提交下的 `content/` 文件，复制内容后在管理端重新保存。

## 六、正文语法

正文按行组织，一行一个元素，空行用于分段。管理端里就是多行文本框。

| 写法 | 效果 |
|---|---|
| `## 小标题` | 二级标题，左侧带渐变竖线 |
| `### 三级标题` | 更小的标题 |
| `- 列表项` | 无序列表 |
| `1. 列表项` | 有序列表 |
| `> 引用内容` | 引用块 |
| `**文字**` | 加粗 |
| 单反引号包裹 | 行内代码，浅色底 |
| `[文字](地址)` | 超链接，新窗口打开 |
| `![说明](图片地址)` | 插入图片，自动缩放 |
| 三个反引号包裹 | 代码块，等宽字体、可横向滚动 |
| 竖线表格 | 见下方示例 |

**表格**用竖线分隔，第二行是分隔线，决定表头：

    | 名称 | 数值 |
    |---|---|
    | 开关频率 | 302 kHz |
    | 电感 | 3.3 µH |

渲染出来是带边框的表格，内容过宽时可以横向滚动。

单元格里要写竖线本身，用反斜杠转义：`\|`。

**完整示例**

    ## 结论

    f_SW = 17820 / R_T(kΩ)，R_T 取 59 kΩ 时约 302 kHz。

    ## 关键参数

    | 项目 | 值 |
    |---|---|
    | 占空比 | 0.625 |
    | 纹波 | 2.84 A |

    - 电容选 C0G
    - 电感 Isat 不低于 15 A

    > 引用用于放结论或校验口径。

上面每行前面的四格缩进只是排版，实际输入时不用缩进。

**其他约定**

- 日期建议写成 `2026-11` 或 `2026-11-06`
